# Среда моделирования распределённых транзакций — фронтенд

Веб-песочница: на холсте собирается микросервисная система (клиенты, шлюзы, сервисы, БД, кэш, брокеры),
её модель запускается под нагрузкой, и видно, как архитектурные решения и паттерны распределённых
транзакций (2PC, сага-оркестрация, сага-хореография, TCC, Outbox) влияют на задержки, отказы и
согласованность данных. Требования — `docs/frontend-spec.md`.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173 — работает с встроенным mock-движком
npm test           # юнит-тесты (Vitest)
npm run e2e        # e2e-сценарии из раздела 2 ТЗ (Playwright; один раз: npx playwright install chromium)
npm run build      # сборка в dist/ (её потом встраивает Go-бинарник через embed)
npm run lint
```

## Архитектура и задел под Go-движок

```
UI (React) ──► store (Zustand) ──► features/sim/controller ──► EngineClient ─┬─► MockEngineClient (сейчас)
                                                                              └─► WsEngineClient   (Go-движок)
```

- **Фронтенд не моделирует систему сам.** Всё общение с движком идёт через один интерфейс
  `EngineClient` (`src/engine/types.ts`). UI не знает, какая реализация активна.
- **Переключение на настоящий движок** — без изменений кода:
  ```bash
  VITE_ENGINE=ws npm run dev                  # REST и WebSocket на /api проксируются на :8080
  ENGINE_URL=http://host:port VITE_ENGINE=ws npm run dev
  ```
  `WsEngineClient` уже реализован: проверка каждого входящего сообщения Zod-схемой, очередь команд
  без соединения, переподключение с экспоненциальной задержкой, статус соединения в верхней панели.
- **Контракт** (формат схемы, команды, сообщения, REST) описан в одном месте — `src/schema/types.ts`
  и `src/engine/types.ts` — и продублирован текстом в `docs/engine-contract.md` для разработки движка.
  Из Zod-схем можно сгенерировать JSON Schema для Go (`zod-to-json-schema`), чтобы стороны не расходились.
- **Mock-движок** (`src/engine/mock/`) — правдоподобная заглушка: сеть очередей
  (загрузка = входящий RPS / ёмкость) плюс эвристики паттернов. Детерминирован по seed.
  Его цифры иллюстрируют работу интерфейса, а не являются результатом для диплома.
- **Хранилище проектов** спрятано за интерфейсом `ProjectRepository` (`src/features/projects/storage.ts`):
  сейчас IndexedDB, при переезде на сервер нужна только REST-реализация.
- **Словарь действий и шаблоны** сейчас лежат во фронтенде (`src/schema/dictionary.ts`,
  `src/features/projects/templates.ts`); шаблоны уже читаются через `EngineClient.getTemplate`,
  поэтому движок может начать отдавать их сам.

## Структура

```
src/
  app/        экраны (стартовый, редактор, маршруты), верхняя панель, общие диалоги
  canvas/     холст React Flow, узлы, связи, Canvas-слой анимации, контекстные меню
  panels/     палитра, панель свойств, нижняя панель
  features/   scaling, endpoints, load, chaos, tracing, metrics, compare, hints, tasks, projects, sim
  engine/     types.ts (контракт), mock/, ws/
  schema/     типы и Zod-схемы, операции, анализ, проверка, импорт/экспорт
  store/      Zustand: project (схема + история), sim (ход запуска), ui
  i18n/       строки интерфейса (ru)
  components/ UI-кит в стиле shadcn/ui, обёртка ECharts
```

## Зависимости вне стека из CLAUDE.md

- `radix-ui`, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react` — то, на чём построены
  компоненты shadcn/ui (диалоги, вкладки, подсказки, меню, иконки).
- `react-resizable-panels` — панели, которые сворачиваются и меняют размер (раздел 4 ТЗ); его же использует
  компонент Resizable из shadcn.
